LeaseLens app map

A snapshot guide to where things live. It can drift as the code changes. Run the app with npm install then npm run dev.

One action: click "Try a sample"

Reference route (not toured interactively)

  1. src/main.ts: showStart() passes onAnalyze, which calls analyze().
  2. src/engine/analyze.ts: analyze splits sentences, runs every rule, merges highlights, scores.
  3. src/ui/lease.ts: renderLease wraps risky sentences in <mark>.

To change this, start here

Add or tune a clause ruleEdit a file in src/engine/rules/, then add a positive and a negative case to tests/rules.test.ts.
Change score weights or bandssrc/engine/score.ts (WEIGHTS, scoreFor, bandFor).
Change colours or fontssrc/styles/tokens.css; tests/design.test.ts checks AA contrast.
Change wording of a messageThe ask text of the rule; the template is in src/engine/messages.ts.

A practice to reuse

Turn each PRD acceptance criterion into a test before polishing. Here, "fair wording must not be flagged" became the negative case per rule in tests/rules.test.ts, which caught heading lines being flagged as clauses. The same approach works on any project with a written spec.
